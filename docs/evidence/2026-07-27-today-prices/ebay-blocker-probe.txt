########## 5. why --write was NOT run
The dry-run's own ceiling is sold_at max 2026-07-25. The DB already holds
source_code='ebay' with max observed_date 2026-07-25 (5,476 rows / 505 variants,
see after-import.txt). market_price_observation's UNIQUE key is
(variant_id, source_code, observed_date), so all 5,420 candidate rows collide with
rows that already exist: zero new observations.

g10_ebay_ingest.py's insert is ON DUPLICATE KEY UPDATE over run_id, effective_at,
price_usd, native_price, native_currency, source_priority, metric_status and
payload_sha256. Running --write would therefore restamp 5,420 existing rows with
tonight's run_id and effective_at while adding no new data — making 07-25 data
carry 07-27 provenance and corrupting the freshness measurement this task exists
to produce. Decision: dry-run only. A genuine new eBay date needs a fresh
grade10-scraper harvest (next scheduled run ~21:17 UTC), which is outside this
task's scope.
